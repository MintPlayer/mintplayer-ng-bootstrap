# PRD: tooltip / popover arrow regression from #458 (and sibling dropped classes)

Status: implemented on `fix/463-overlay-arrow-regression`, 2026-11-06. Issue #463. Regression introduced
by 290f224cd (#458, PR #459, "all UI fronts generated from D10 sources"). Spike outcomes are in §5a.

## 1. Symptom (verified live)

`https://bootstrap.mintplayer.com/overlays/tooltip` (Angular demo, v22.34.0), measured with Playwright:

| Placement | Trigger box (x,y,w,h) | Panel box | Arrow box | Arrow `position` |
|---|---|---|---|---|
| top    | 892,285,52,38 | 873,223,90,56 | 867,223,13,6 | `static` |
| bottom | 548,339,79,38 | 543,383,90,56 | 537,383,13,6 | `static` |
| start  | 561,285,52,38 | 465,273,90,63 | 465,267,6,13 | `static` |
| end    | 886,339,63,38 | 955,327,90,63 | 955,321,6,13 | `static` |

- The **panel** is placed correctly: centred on the trigger, with a 6px gap for the arrow.
- The **arrow** is in normal flow. It is always the first row of the panel, at its top-left. Bootstrap's
  per-side offsets (`bottom: calc(-1 * arrow-height)` …) do nothing on a static box. `translateX(-50%)`
  still applies, so the arrow pokes half its width out past the panel's left edge.
- The panel is 6px too tall (inner 50px + 6px arrow row).

## 2. Root cause

Stock Bootstrap 5.3 never positions `.tooltip-arrow` / `.popover-arrow` itself
(`node_modules/bootstrap/scss/_tooltip.scss:32-35`, `_popover.scss:40-43`: display, width, height
only). Popper does that with inline `position: absolute`.

- **Before #458** the Angular templates carried it as a utility:
  `class="tooltip-arrow position-absolute"` (same for `popover-arrow`), at 547927024.
- **#458 M6** moved both to D10 groups. The arrow bags became plain `{ class: 'tooltip-arrow' }`
  (`libs/mintplayer-ui-core/tooltip/src/tooltip.core.ts:83`) and `{ class: 'popover-arrow' }`
  (`libs/mintplayer-ui-core/popover/src/popover.core.ts:107`). The scoped sheets ported the
  `left: 50%` / `transform` rules but not the position:
  - `tooltip/src/styles/tooltip.scoped.scss:13-23`
  - `popover/src/styles/popover.scoped.scss:13-23`

**This is not a missing global utility.** `.position-absolute` is still in the page baseline and still
computes `absolute` on the live page. The class was dropped from the markup.

**Why no test caught it.**
- The tooltip unit specs (`tooltip.core.spec.ts`, `tooltip.aria.spec.ts`) run in jsdom and assert
  classes, ARIA and timing only.
- No front has a tooltip spec any more (the Angular one was deleted in #458).
- The only e2e coverage, `apps/ng-bootstrap-demo-e2e/e2e/keyboard-walkthrough.spec.ts:94-124`, asserts
  `toBeVisible()`.
- Nothing asserts geometry.

## 3. Fix

Add `position: absolute` to the arrow in each group's scoped sheet:

```scss
.tooltip .tooltip-arrow { position: absolute; }           // tooltip.scoped.scss
.popover > .popover-arrow { position: absolute; }         // popover.scoped.scss
```

**Why the sheet and not the `position-absolute` utility in the bag.** CLAUDE.md C4 says a scoped sheet
carries what Bootstrap lacks, and "what Popper writes inline" is exactly that. These sheets already
replace Popper's other inline styles (`position: fixed`, the anchored left/top, arrow centring).
Splitting that replacement between a sheet and a utility class would put it in two places. The panel's
`position: fixed` is the arrow's containing block, so no `position-relative` is needed.

**Scope of the fix.** One sheet edit covers all four fronts. Angular, React, Vue and Lit all install the
same `tooltipScopedStyles` / `popoverScopedStyles`:
- Angular: `tooltip-panel.component.generated.ts:29`
- React: `BsTooltipPanel.generated.tsx:24`
- Vue: `BsTooltipPanel.generated.vue:21`
- Lit: `mp-tooltip-panel.generated.ts:51`

`*.scoped.styles.ts` is gitignored and regenerated by `nx run mintplayer-ui-core:codegen`.

## 4. Sibling regressions: the same pattern elsewhere in #458

A sweep compared the deleted Angular templates (547927024) with the new cores, views and sheets. It
found these dropped utility classes. None has been verified in a browser yet; the spikes below cover
that.

| Component | Old class | Now | Expected impact |
|---|---|---|---|
| popover arrow | `position-absolute` | missing (`popover.core.ts:107`) | **Visible, same as the tooltip** |
| offcanvas panel | `overflow-x-hidden` (start/end) / `overflow-y-hidden` (top/bottom), from `overflowClass()` | missing (`offcanvas.core.ts:90`, sheet) | Wide content may spill or scroll sideways |
| alert wrapper | `mb-3 overflow-hidden` around `alert mb-0` | `.alert` with stock margin (`alert.core.ts:41`) | Margin matches; the collapse animation may be unclipped |
| resizable wrapper | `h-100` | missing (`resizable.core.ts:169`) | Possible height change |
| toast | `d-block fade mb-2 me-2` | `toast fade show` (`toast.core.ts:61-65`) | Only `me-2` lost; cosmetic |

These were checked and are fine: modal (`d-block` moved to its sheet), marquee, table, file-upload,
scrollspy, typeahead, sticky-footer, color-picker. The badge, dropdown-menu, has-overlay and modal-host
templates had no utility classes.

## 5. Spikes

Each spike is small, ends in a yes/no answer, and feeds the milestones below. Use the `playwright_node`
MCP against the local demos, comparing with the last pre-#458 deploy if one is available.

- **S1. Popover confirm (about 5 min).** On `/overlays/popover`, measure the arrow's computed position
  and box for all four placements, the same way as §1. Expected: `static`, wrong place. If so, it joins
  M1.
- **S2. Offcanvas overflow.** Open start/end and top/bottom offcanvases with content wider or taller
  than the panel. Does it overflow or scroll on the wrong axis compared with stock Bootstrap
  `.offcanvas` (which sets no overflow on the panel, only `overflow-y: auto` on `.offcanvas-body`)?
  - Decide whether the old `overflow-*-hidden` was load-bearing (for example during the slide
    transition) or legacy.
  - If it is needed, it goes in `offcanvas.scoped.scss`, not the bag (same reasoning as §3).
- **S3. Alert collapse.** Dismiss an alert in the demo. Without the wrapper's `overflow-hidden`, does
  the content paint outside the collapsing box during the height animation? If yes, restore clipping in
  `alert.scoped.scss` on the collapsing element.
- **S4. Resizable height.** Compare `/advanced/resizable` (or its demo route) heights before and after.
  Was `h-100` what let a resizable fill a fixed-height parent? Fix in the sheet if so.
- **S5. Toast spacing.** Is the lost `me-2` visible? It probably mattered only in the old non-container
  layout. If it isn't visible, close the spike with no change.
- **S6. Regression guard design.** Pick the cheapest guard that would have caught this.
  - (a) A geometry e2e per positioned overlay: arrow computed `position` is `absolute`, the arrow lies
    outside the panel's edge on the placement side, and the arrow's centre is within 1px of the panel's
    centre on the cross axis. Copy the `boundingBox()` pattern from `navbar.spec.ts:128`.
  - (b) A conformance spec in ui-core that renders each panel view into a real browser. This is
    heavier; reject it unless (a) cannot cover React and Vue.
  - Recommendation going in: (a), in a new `apps/ng-bootstrap-demo-e2e/e2e/tooltip.spec.ts`
    (tooltip + popover), plus the same spec in the React and Vue e2e apps, which have no tooltip
    coverage at all.

## 5a. Spike outcomes (measured on the live Angular demo, master at eb70cbb18)

- **S1, popover: confirmed.** The arrow is `static` on all four sides, for example top: panel
  779,181–1055,301 and arrow 772,182 (16×8), at the panel's top-left. With `position: absolute`
  injected, the top arrow spans 909–925 × 301–309: centred on the panel (x 917) and filling the gap
  to the trigger (y 309). The other three sides check out the same way. **Fixed in M1.**
- **S1, tooltip after the fix** (injected): top panel 873,229–963,279, arrow 912–924 × 279–285.
  The panel loses its 6px arrow row. The core's gap (`GAP`, the arrow height, `tooltip.core.ts:63`)
  is applied after measuring the panel, so the arrow exactly fills the gap on all four sides.
- **S2, offcanvas: restored.** `.offcanvas-body` scrolls its own overflow (`overflow: auto`, measured
  scrollWidth 3000 against clientWidth 384), but the panel itself is `overflow: visible`. So a header
  wider than a side panel paints over the page, which the old `overflow-x-hidden` / `overflow-y-hidden`
  prevented. Restored as cross-axis clipping in `offcanvas.scoped.scss`.
- **S3, alert: no change.** The D10 alert toggles `hidden` and has no height animation, so the old
  wrapper's `overflow-hidden` has nothing to clip. The 1rem bottom margin comes from Bootstrap's
  `.alert`.
- **S4, resizable: no change.** The old `h-100` sat on an inner wrapper that no longer exists. The
  D10 root is the box itself (`resizable border position-*`), and all eight glyphs measure on its edges.
- **S5, toast: no change.** The toasts sit 16px from the container's edge (`p-3`) and stack 24px apart
  (`--bs-toast-spacing`). That is stock Bootstrap; the old `me-2` / `mb-2` predate `.toast-container`.
- **S6, guard: option (a).** `tools/e2e-shared/overlay-arrow-suites.ts`, run by
  `overlay-arrow.spec.ts` in the ng, React and Vue e2e apps. For every trigger it checks:
  - the arrow is `position: absolute`;
  - the arrow lies outside the panel's edge on the side the panel actually landed (read from its
    `bs-*-<side>` class, so a flip doesn't break the test);
  - the arrow is centred on that edge, within 1.5px.
