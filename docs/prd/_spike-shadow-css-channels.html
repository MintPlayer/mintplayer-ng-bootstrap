What colour reaches what, across a shadow boundary

GREEN = page stylesheet, paints consumer markup   RED = mp-badge's own shadow   BLUE = a component's own shadow, its own nodes

A · Baseline — consumer markup in the page

<div>                        ← light DOM
  <span class="consumer">    ← expect GREEN
    <mp-badge>               ← expect RED (own shadow)

B · BROKEN — component appends consumer markup into its shadow root

<broken-el>
  #shadow-root  ← SHADOW
    <span class="consumer">  ← expect GREEN, page CSS cannot enter
      <mp-badge>             ← expect RED (carries its own styles)

C · FIX A (D2) — shadow root kept, consumer markup slotted

<slot-el>
  #shadow-root  ← SHADOW ── <div class="owned"> BLUE
                         └─ <slot>
  <span class="consumer" slot="c">  ← light DOM, expect GREEN
    <mp-badge>                      ← expect RED

D · FIX B (D8) — component mounts its markup in its own light DOM

<light-el>
  #shadow-root  ← SHADOW ── <slot>
  <div>                            ← light DOM, built by the component
    <mp-cell class="owned">        ← BLUE from mp-cell's own shadow
    <span class="consumer">        ← expect GREEN
      <mp-badge>                   ← expect RED

E · Leak check — a page node named the same as a component's internals

<div class="owned">   ← page owns this. Expect the page's GREY (#eee),
                         never BLUE. Proves nothing escapes a shadow root.
page-owned node

F · A web component inside a web component

<n-table>  #shadow  ← :host([striped]) sets --n-row-bg
  <n-tr>   #shadow  ← :host(:hover)    sets --n-cell-bg
    <n-td> #shadow  ← background: var(--n-cell-bg, var(--n-row-bg))
      <mp-badge class="consumer">   ← 3 slot hops from the table

Does the badge still work three levels deep? And can a container restyle it from outside? The second answer is no, in two of three shapes — which is the trap, not a bug.
